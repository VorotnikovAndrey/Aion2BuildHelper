# CLAUDE.md — правила для AI-агентов

Этот файл читают AI-агенты (Claude Code и др.), которые пишут код в репозитории. Коротко и по делу.

## Контекст

- **Aion2 Build Helper** — десктоп-приложение (Electron) для владельца репозитория: помогает собрать персонажа в AION 2 по выбранному гайду. Версия — в `package.json`, история — в `CHANGELOG.md`.
- **Личный инструмент.** Не продаётся и не распространяется. Основной персонаж владельца — страж (Templar), PvE. Но ничего не зашиваем под персонажа или гайд: всё работает для любого класса, персонажа и гайда.
- **Владелец код не пишет** — ставит задачи и проверяет результат. Объясняйте решения просто. Владелец доверяет решения агенту: не ждите одобрений на мелочи, но outward-действия (push, публикация) — только по просьбе.
- **Язык:** интерфейс, документация, комментарии и коммиты — **на русском**. Идентификаторы — на английском. Игровые названия — двуязычные (русский перевод приложения + официальный английский).
- **Планка качества** — как у соседнего проекта IndieRocket (`D:\Work\Fork\IndieRocket`): аккуратный интерфейс, тесты на логику, документация, автоскриншоты.

## Где что лежит

```
src/shared/            — чистая логика без Electron и React. Покрыта тестами.
  types.ts             — модель персонажа
  questlog/parse.ts    — разбор characters.json оверлея Questlog
  gamedata/            — справочники: статы, умения+специализации, слоты, арканы, доски, род, опции шмота
  gamedata/generated/  — JSON, собранный скриптом npm run gamedata (руками не править)
  guide/               — формат гайда, проверка импорта, встроенные гайды (builtin/)
  analysis/            — разбор персонажа по гайду: skills, gear, arcana, daevanion, genus, pets, build (итог+шаги), history
  names.ts             — как называть сущности (ru/en/оба + свои названия пользователя)
  api.ts               — контракт window.api
src/main/              — Electron: окно, IPC, чтение и слежение за файлом оверлея, хранилище, автоскриншоты
src/preload/           — мост window.api
src/renderer/          — интерфейс (React). lib/webApi.ts — тот же API для браузерного режима
scripts/gamedata/      — сборка справочников (metabot.gg + локальный Questlog)
docs/                  — документация, начните с docs/README.md
samples/private/       — реальные данные игрока для локальной проверки. НЕ в git.
```

Подробно — [docs/architecture.md](docs/architecture.md).

## Команды

```bash
npm run dev        # приложение с горячей перезагрузкой
npm run dev:web    # тот же интерфейс в браузере: http://localhost:5199 (данные — из файла оверлея)
npm test           # unit-тесты (vitest)
npm run typecheck  # проверка типов
npm run shots      # сборка + автоскриншоты всех экранов в out/shots (на реальных данных оверлея)
npm run format     # prettier
npm run gamedata   # обновить справочники (по умолчанию — страж; --classes all — все классы)
npm run icon       # перерисовать build/icon.png и icon.ico
npm run shortcut   # ярлык на рабочем столе
```

Node.js установлен в `C:\Program Files\nodejs`. Если `node` не находится в PATH, добавьте этот путь в начало `PATH` в текущей сессии.

## Как проверять свою работу

1. `npm run typecheck` и `npm test` — без ошибок.
2. Менялся интерфейс — **`npm run shots`, затем смотрите PNG в `out/shots`**. Либо `npm run dev:web` и браузер на `http://localhost:5199/?static` (`?static` выключает анимации — в фоновой вкладке они замирают на середине).
3. Новая логика в `src/shared` — с тестом рядом (`*.test.ts`).
4. `samples/private/characters.json` (копия файла оверлея) включает тест на реальных данных: `SHOW=1 npx vitest run src/shared/analysis/real.test.ts --silent=false` печатает итог и шаги.

## Правила кода

- **Логика — в `src/shared`, без React и Electron.** Интерфейс только показывает то, что посчитал `analysis/*`.
- **Всё — по игровым ID.** Названия берутся через `Namer` (`names.ts`), никогда не пишите игровые названия строкой в логике. Новые русские названия — в `gamedata/stats.ts` / `gamedata/skills.ts`.
- **Цвета — только токены** из `src/renderer/src/styles.css` (`bg-surface`, `text-ink-2`, `text-accent`…). Hex в компонентах не пишем. Статус — всегда с подписью или иконкой, не только цветом. См. [docs/design.md](docs/design.md).
- **Сгенерированные справочники не правим руками** — только через `npm run gamedata` (скрипт кэширует страницы в `.cache/`).
- **Честность данных.** Если данные оверлея сомнительны (пример: специализации у всех умений «1, 2» — это открытые слоты, а не выбор), интерфейс так и говорит и даёт поправить вручную. Свои догадки (приоритеты статов, которых нет в гайде) помечаем как «оценка помощника».
- **Формат гайда меняется осторожно**: старые файлы гайдов должны импортироваться (`normalizeGuide`). Поле `schema` — на будущее.
- **Хранилище** — JSON-файлы в `%APPDATA%\Aion2 Build Helper` (настройки, свои гайды, история, последний снимок персонажа). Запись — через временный файл.
- Комментарии — зачем, а не что. Короткие.

## Документация — часть работы

После заметного изменения обновите: `CHANGELOG.md` (что изменилось для игрока), нужный файл в `docs/`, при новом решении — запись в `docs/decisions/`. Для возврата к контексту читайте `docs/README.md` — там же «что известно и что под вопросом».
