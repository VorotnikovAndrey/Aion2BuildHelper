# 0010 — Перевод интерфейса на 9 языков

**Дата:** 2026-11-10 · **Статус:** принято

## Контекст

Владелец попросил локализацию «на все популярные языки и обязательно на украинский». До этого интерфейс был только русским: около 1 400 строк прямо в коде (страницы, подсказки, тексты разбора в `shared/analysis`, тексты встроенных гайдов), игровые названия — русские или английские.

## Решение

- **Языки — языки клиента игры + украинский.** У глобальной версии AION 2 (и у базы Questlog) — английский, немецкий, французский, испанский, португальский, японский, корейский и русский. К ним — украинский. Отбор не «по числу говорящих», а по тому, на каких языках играют в эту игру; польский, турецкий, китайский и т. п. добавляются так же (файл словаря + строка в `LOCALES`).
- **Ключ — русский текст** (как в gettext): `t('Не хватает {n}')`, числительные — `tn(n, '{n} умение|{n} умения|{n} умений')`. Код остаётся читаемым, русский интерфейс не зависит от словарей, а недостающий перевод показывается по-русски, а не пустым ключом. Словари — `src/shared/i18n/locales/<язык>.json` (русский текст → перевод; у числительных — формы CLDR `{ one, few, many, other }`).
- **Язык выбирается при загрузке окна** (`?lang=` от main-процесса), а смена языка перезагружает окно. Поэтому `t()` можно звать где угодно — в константах модулей, в `shared/analysis`, при сборке встроенных гайдов — и ничего не останется на старом языке. Первый запуск берёт язык системы (`app.getPreferredSystemLanguages()`), у старых настроек без поля — русский.
- **Перенос существующего кода — инструментом** (`scripts/i18n/wrap.mjs`, по AST через Babel): строки, шаблоны `${…}` → `{подстановки}`, текст JSX вместе с простыми `{выражениями}` — одна фраза. Не трогает ключи объектов, сравнения, `case`, официальные названия в справочниках (`ru:` и таблицы по ID).
- **Встроенные гайды** хранят свои тексты не строкой, а ключом: генератор пишет `{ "$t": "…", "p": {…} }`, `{ "$skill": ID }`, `{ "$join": […] }`, при загрузке их собирает `shared/guide/localize.ts`. Тексты авторов билдов остаются как есть.
- **Игровые названия не переводим сами.** Официальные названия есть в справочниках только русские и английские, поэтому выбор (вкладка «Язык»): «как интерфейс» (русские при русском, иначе английские), «русские», «английские», «как интерфейс + английские». Для справочников `{ ru, en }` — `term()` (`names.ts`), для умений, статов и вещей — `Namer`. Тексты переводов пишут игровые термины официальными английскими названиями (АТК → ATK, Знание о видах → Genus Insight), чтобы совпадать с тем, что показывают справочники.
- **Переводы сделал помощник** (по языку на переводчика, с общим глоссарием официальных английских терминов — `.cache/i18n/glossary.json` собирается из справочников). В интерфейсе это сказано в настройке языка.

## Последствия

- **Любая новая строка интерфейса — через `t()` / `tn()`** со строковым литералом (иначе ключ не собрать), и сразу с переводом во все словари. `npm run i18n` показывает, чего не хватает; тест `src/shared/i18n/i18n.test.ts` не пропустит недостающий, лишний ключ или потерянную подстановку.
- Своя переменная с именем `t` внутри файла перекрывает перевод — так не называем.
- Официальные названия на немецком, японском и других языках клиента можно добавить позже: собрать их с базы Questlog на этом языке (как русские) и расширить `GameLang` в `names.ts`.
- Числа и даты форматируются по языку интерфейса (`intlLocale()`); японский и корейский — системными шрифтами (Yu Gothic, Malgun Gothic), в Inter этих знаков нет.
